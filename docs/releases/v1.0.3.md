# nanoMuse 1.0.3 · Helm

🐉 **nanoMuse `1.0.3` “Helm”**: the chat looks the same on every device now, a video of your own can be the face, several custom endpoints work side by side, and a day of reports from one careful tester is answered.

1.0.2 went out on 2026-10-11. The same day @Ichiro786 finished a redesign of the Android app in three pull requests: the bottom bar became a floating frosted-glass pill, the chats drawer and the chat itself moved onto the theme's own canvas with black and white pills instead of blue, and the header became a soft scrim the conversation slides under ([#329](https://github.com/nano-muse/nanoMuse/pull/329), [#330](https://github.com/nano-muse/nanoMuse/pull/330), [#331](https://github.com/nano-muse/nanoMuse/pull/331)). We took that look as the reference and brought it to the iPhone, the web console and the desktop, so the five clients read as one app. @Mola-maker read the Android code and the tests and filed ten reports in an afternoon, from an own Anthropic key that could not send to a debug log that held raw API keys ([#332](https://github.com/nano-muse/nanoMuse/issues/332) to [#340](https://github.com/nano-muse/nanoMuse/issues/340), [#347](https://github.com/nano-muse/nanoMuse/issues/347)); every one of them is fixed here. Two requests became features: a clip of your own as the agent's face ([#324](https://github.com/nano-muse/nanoMuse/issues/324)) and more than one OpenAI-compatible endpoint at a time on the desktop and in the web console ([#294](https://github.com/nano-muse/nanoMuse/issues/294)). Nothing moves for a person upgrading: the Android package installs over 1.0.2 and keeps everything, the desktop keeps its settings and its one custom endpoint becomes the first of the list, and a 1.0.2 client works against the relay (0.24.2) unchanged.

## Highlights

- **One look on every device.** The bottom bar on Android, iPhone and the web's phone layout is a floating frosted-glass pill, as wide as the composer above it (420 at most, centred on a wider screen), icons only; the current tab shows its filled glyph on an ink disc, black in the light theme and white in the dark one, that springs across to the tab you tap. The chat is monochrome on all four clients: your messages are black pills with white text in light and white pills with black text in dark, the agent's replies sit in a pill a shade off the canvas, the send button and the scroll-to-latest disc are the same ink, the light canvas is plain white, and the header is a scrim the conversation scrolls under instead of a bar with a line. On Android the chats drawer and the menus sit on the same canvas, with a hairline edge instead of a tinted sheet ([#329](https://github.com/nano-muse/nanoMuse/pull/329), [#330](https://github.com/nano-muse/nanoMuse/pull/330), [#331](https://github.com/nano-muse/nanoMuse/pull/331) by @Ichiro786; iPhone, web and desktop follow them).
- **A clip of your own as the face.** On Android, iPhone and the desktop the pen on the face and the avatar studio offer *Your own clip…*: the system's video picker, then a preview of the clip playing in the face's round frame with *Use* and *Cancel*. One clip, MP4 or MOV with H.264 (the iPhone also takes HEVC), at most 15 seconds and 30 MB; it plays muted in a loop for the mood at rest and stands in for every other mood, the drawn stills keep their place where a still is shown, and with no drawn face the clip's first frame is the still. The clip stays on the device that chose it, is never sent to nanoMuse Cloud and does not sync; *Default face* takes it off again. A longer, larger or differently encoded clip is refused with a sentence that states the limits ([#324](https://github.com/nano-muse/nanoMuse/issues/324), requested by @Yicheng-1218).
- **Several custom endpoints at once.** The desktop and the web console used to hold one OpenAI-compatible endpoint, so a second one could only replace the first. The custom row is a list now: each endpoint has a name, an address, its own key and its models, the picker groups the models by endpoint, and any of them can take a job. An existing single endpoint becomes the first entry without asking. The phones already worked this way ([#294](https://github.com/nano-muse/nanoMuse/issues/294), requested by @Alasco123).
- **Ten reports on the Android app, all fixed.** An own Anthropic key sends again: the provider read the Claude Code OAuth identifier on every request, and the public build ships it empty, so every message on an own key stopped before it left the phone ([#333](https://github.com/nano-muse/nanoMuse/issues/333)). A carriage return in tool output overwrites instead of erasing, so `AAAA\rBB` reads `BBAA` and a progress line no longer truncates the result the model sees ([#334](https://github.com/nano-muse/nanoMuse/issues/334)). Leaving the sign-in page or the network page cancels its request instead of holding the connection to the timeout ([#336](https://github.com/nano-muse/nanoMuse/issues/336)). A new set of avatar candidates no longer shows the old set's failures ([#337](https://github.com/nano-muse/nanoMuse/issues/337)). Stop right after the first message no longer saves the welcome lines as the model's reply, and puts your text back in the composer ([#340](https://github.com/nano-muse/nanoMuse/issues/340)). The debug request log masks credential headers and keeps its own copy ([#347](https://github.com/nano-muse/nanoMuse/issues/347)). Icon-only controls (the password eye, the add buttons, Like, the avatar tiles) have names for a screen reader, in all 17 languages ([#338](https://github.com/nano-muse/nanoMuse/issues/338)). And the tests: the on-device test set compiles again and CI keeps it so, the upstream provider tests feed the streams the provider actually reads, CI runs the OpenMinis provider and sandbox tests beside ours, and the runtime's web tests no longer depend on the machine's resolver ([#332](https://github.com/nano-muse/nanoMuse/issues/332), [#335](https://github.com/nano-muse/nanoMuse/issues/335), [#339](https://github.com/nano-muse/nanoMuse/issues/339)). All reported by @Mola-maker.
- **A voice prompt from the Action Button (iPhone).** A *Voice Prompt* Shortcut opens the app and starts listening, so a prompt can be spoken instead of typed: bind it to the Action Button, Back Tap or a widget, press, speak, and the words appear in the composer; sending stays a tap. Written by @cypggs ([#298](https://github.com/nano-muse/nanoMuse/pull/298)).
- **OpenCode Go on every client.** Go, the subscription beside Zen on the same host, asks a client to name itself and send one id per conversation; the runtime, the phones and the desktop now do, so Go is back in the own-key catalogue, and the relay's guidance lists it apart so that a 1.0.1 phone, which does not send the id, never offers it ([#325](https://github.com/nano-muse/nanoMuse/pull/325) by @PovedaAqui).
- **A freshly installed desktop update is no longer offered to itself.** The daily update check kept its result for a day and the file outlived the update, so right after installing 1.0.2 the sidebar still said *Update to 1.0.2*; the cached result is now read against the version that runs ([#341](https://github.com/nano-muse/nanoMuse/issues/341), reported by @jiangkaiqi2005).
- **Smaller things.** The relay's Docker image runs as an unprivileged user (uid 10001) and says in one sentence what to do when its data directory is not its own; the runtime's image reports its health to `docker ps`; the unused `POST /api/avatar/estimate` is gone; every field on the web console's Connections screen is named for a screen reader; the feed's and a goal's daily time is written in plain digits on every phone; every pull request carries its platform and kind labels, and the contributor guide says plainly that an issue stays open until a maintainer closes it.
- **TestFlight.** Build 16 (1.0.0) is what the public link installs today; builds 18 (1.0.1) and 19 (1.0.2) are still in Apple's beta review; 1.0.3 goes up as build 22 and is submitted to the same review. The link installs a build once its review has passed, the internal testers before that.

## Upgrade Notes

- **Android installs over 1.0.2 and keeps your data.** `nanoMuse-1.0.3-arm64.apk` (Android 8.0+, arm64; versionCode 46) is signed with the same key as every version before it. Verify with `sha256sum -c nanoMuse-1.0.3-arm64.apk.sha256`. The bottom bar, the drawer and the chat look different; nothing else moved.
- **iPhone and iPad come through TestFlight.** The public link installs build 16 (1.0.0), which passed Apple's beta review; builds 18 and 19 are still in that review, and build 22 (1.0.3) is submitted when it is uploaded; a build reaches the link once its review has passed, the internal testers before that.
- **The desktop installers are built by CI from `main` one commit after the tag `v1.0.3`** (the tag's Windows build failed on a test that read line endings, fixed in [#376](https://github.com/nano-muse/nanoMuse/pull/376); the desktop sources are those of the tag). The Mac packages are not notarized: the first time, open the app from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*). The Windows package is not signed: click *More info* and *Run anyway* once. On Linux prefer the `.deb`; the AppImage needs FUSE (`--appimage-extract-and-run` without). They arrive a little after the APK, and `SHA256SUMS-desktop.txt` lists every checksum. Your one custom endpoint becomes the first entry of the new list; the key stays where it was.
- **The relay is 0.24.2; nothing changes on the wire.** A 1.0.2 client works against it unchanged. Its Docker image now runs as uid 10001, so a bind-mounted data directory must belong to that uid: `sudo chown -R 10001:10001 data` once (`scripts/self-host.sh` does it for you), and a relay that cannot write the directory says so at start instead of printing a traceback; [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/self-hosting.md) has the steps.
- **The runtime's HTTP API lost one route.** `POST /api/avatar/estimate` had no caller; everything else is as it was, and `config.toml` keeps every key it had.

## Community

nanoMuse is open source, free and non-profit. Sign in with a phone number or an e-mail and you get a starting allowance; the developer pays for it. The account page shows what is left and how to add more. When it is gone, use your own key or a plan you already pay for ([how](https://github.com/nano-muse/nanoMuse/blob/main/docs/own-key.md)); the key you add can take over any of the four jobs, and the account can be switched off as a model source while you keep it for sync and your devices. With an account, the text of your main conversation is kept on nanoMuse Cloud so that your devices show the same chat, side chats only if you say so, and one switch in Data controls turns it off and deletes it; nothing is sold ([privacy policy](https://nanomuse.cn/privacy/)); delete the account whenever you want. The same relay runs on a server of yours: [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/self-hosting.md).

🐉 **nanoMuse `1.0.3`「Helm」**：聊天在每台设备上长得一样了，可以用自己的一段视频当形象，多个自定义端点能并排用，还有一位细心测试者一天里报来的问题都有了答复。

1.0.2 在 2026-10-11 发出。同一天 @Ichiro786 用三个 PR 做完了 Android App 的改版：底栏变成悬浮的毛玻璃胶囊，聊天抽屉和聊天本身搬到主题自己的底色上、用黑白药丸代替蓝色，顶栏变成一层柔和的遮罩，对话从它底下滑过去（[#329](https://github.com/nano-muse/nanoMuse/pull/329)、[#330](https://github.com/nano-muse/nanoMuse/pull/330)、[#331](https://github.com/nano-muse/nanoMuse/pull/331)）。我们把这个样子当作参照，带到了 iPhone、网页控制台和桌面端，五个客户端读起来是同一个 App。@Mola-maker 读了 Android 的代码和测试，一个下午报了十个问题，从发不出去的自有 Anthropic key 到存着原始 API key 的调试日志（[#332](https://github.com/nano-muse/nanoMuse/issues/332) 到 [#340](https://github.com/nano-muse/nanoMuse/issues/340)、[#347](https://github.com/nano-muse/nanoMuse/issues/347)）；这里每一个都修了。两个请求做成了功能：用自己的一段视频当智能体的脸（[#324](https://github.com/nano-muse/nanoMuse/issues/324)），以及桌面端和网页控制台同时配置多个 OpenAI 兼容端点（[#294](https://github.com/nano-muse/nanoMuse/issues/294)）。升级的人什么都不用挪：Android 安装包覆盖安装 1.0.2、数据全部保留，桌面端保留设置、原来那一个自定义端点成为列表里的第一项，1.0.2 的客户端对着新中继（0.24.2）照常工作。

### 亮点

- **每台设备上同一个样子。** Android、iPhone 和网页的手机布局里，底栏是一枚悬浮的毛玻璃胶囊，和上面的输入框一样宽（最宽 420，更宽的屏幕上居中），只有图标；当前标签页的填充图形垫在一块墨色圆盘上，浅色主题黑、深色主题白，点下一个标签时它弹过去。四个客户端的聊天都是单色的：你的消息在浅色下是黑底白字的药丸、深色下是白底黑字，智能体的回复在一块比底色略深一级的药丸里，发送键和「回到最新」圆盘用同一种墨色，浅色底是纯白，顶栏是对话从底下滑过去的一层遮罩，而不是带一条线的横条。Android 上聊天抽屉和菜单也在同一个底色上，用一圈细线代替染色的面板（[#329](https://github.com/nano-muse/nanoMuse/pull/329)、[#330](https://github.com/nano-muse/nanoMuse/pull/330)、[#331](https://github.com/nano-muse/nanoMuse/pull/331)，@Ichiro786；iPhone、网页和桌面端跟着改）。
- **用自己的一段视频当脸。** Android、iPhone 和桌面端上，脸上的那支笔和形象工作室多了「自己的视频…」：系统的视频选择器，然后在脸的圆框里预览播放，有「使用」和「取消」。一段视频，MP4 或 MOV、H.264 编码（iPhone 也收 HEVC），最长 15 秒、最大 30 MB；它静音循环播放，用于待机状态，也顶替其他每种情绪，画出来的静态图在需要静态图的地方照旧，没有画过脸时用视频的第一帧当静态图。视频只留在选它的那台设备上，不上传 nanoMuse Cloud，也不同步；「默认形象」把它拿掉。更长、更大或编码不同的视频会被拒绝，并用一句话说明限制（[#324](https://github.com/nano-muse/nanoMuse/issues/324)，@Yicheng-1218 提出）。
- **多个自定义端点同时用。** 桌面端和网页控制台以前只放得下一个 OpenAI 兼容端点，第二个只能顶掉第一个。现在自定义那一行是一个列表：每个端点有名字、地址、自己的 key 和模型，选择器按端点分组列出模型，任何一个都能接活。已有的那一个端点会直接成为第一项，不用再问。手机 App 本来就是这样（[#294](https://github.com/nano-muse/nanoMuse/issues/294)，@Alasco123 提出）。
- **Android 的十个报告，全部修好。** 自有 Anthropic key 又能发了：provider 在每个请求上都去读 Claude Code 的 OAuth 标识，而公开构建里这个值是空的，所以用自有 key 的每条消息还没离开手机就停了（[#333](https://github.com/nano-muse/nanoMuse/issues/333)）。工具输出里的回车是覆盖而不是抹掉，`AAAA\rBB` 读出来是 `BBAA`，进度行不再截断模型看到的结果（[#334](https://github.com/nano-muse/nanoMuse/issues/334)）。离开登录页或网络页会取消它的请求，而不是把连接挂到超时（[#336](https://github.com/nano-muse/nanoMuse/issues/336)）。新一组形象候选不再显示上一组的失败（[#337](https://github.com/nano-muse/nanoMuse/issues/337)）。刚发出第一条消息就点停止，不再把欢迎语存成模型的回复，并把你的文字放回输入框（[#340](https://github.com/nano-muse/nanoMuse/issues/340)）。调试请求日志打码凭据头并保存自己的副本（[#347](https://github.com/nano-muse/nanoMuse/issues/347)）。只有图标的控件（密码的眼睛、添加按钮、点赞、形象格子）给读屏软件加了名字，十七种语言都有（[#338](https://github.com/nano-muse/nanoMuse/issues/338)）。还有测试：真机测试集又能编译了、CI 会一直盯着，上游 provider 的测试喂的是 provider 真正读的流，CI 在我们的测试之外也跑 OpenMinis 的 provider 和沙箱测试，运行时的网页工具测试不再依赖机器的 DNS（[#332](https://github.com/nano-muse/nanoMuse/issues/332)、[#335](https://github.com/nano-muse/nanoMuse/issues/335)、[#339](https://github.com/nano-muse/nanoMuse/issues/339)）。都是 @Mola-maker 报的。
- **操作按钮发起语音提示（iPhone）。** 一个「语音提示」快捷指令打开 App 并开始听，于是提示可以说而不是打：把它绑到操作按钮、轻点背面或小组件上，按下、说话，文字出现在输入框里；发送仍然是点一下。@cypggs 写的（[#298](https://github.com/nano-muse/nanoMuse/pull/298)）。
- **OpenCode Go 在每个客户端上可用。** Go 是和 Zen 同一域名上的订阅，要求客户端表明身份并给每个对话发一个 id；运行时、手机和桌面端现在都这么做，所以 Go 回到了自有 key 目录，中继的指引把它单独列出，让不发 id 的 1.0.1 手机永远不会看到它（[#325](https://github.com/nano-muse/nanoMuse/pull/325)，@PovedaAqui）。
- **刚装好的桌面端更新不再提示更新到自己。** 每日更新检查的结果会保留一天，文件在更新后还在，所以刚装完 1.0.2 侧栏仍然说「更新到 1.0.2」；现在缓存的结果会对照正在运行的版本读取（[#341](https://github.com/nano-muse/nanoMuse/issues/341)，@jiangkaiqi2005 报告）。
- **小的事情。** 中继的 Docker 镜像以非特权用户（uid 10001）运行，数据目录不属于它时会用一句话说明该怎么做；运行时的镜像向 `docker ps` 报告健康状态；没人调用的 `POST /api/avatar/estimate` 删掉了；网页控制台连接页的每个字段都给读屏软件起了名字；动态和目标的每日时间在每部手机上都用普通数字写；每个 PR 都带上平台和类型标签，贡献指南明说 issue 由维护者决定何时关闭、默认留着。
- **TestFlight。** 公开链接今天装到的是第 16 个构建（1.0.0）；第 18 个（1.0.1）和第 19 个构建（1.0.2）还在 Apple 的测试版审核中；1.0.3 以第 22 个构建上传并提交同一审核。审核通过的构建就会给到链接，内部测试员在那之前就能用。

### 升级说明

- **Android 覆盖安装 1.0.2，数据保留。** `nanoMuse-1.0.3-arm64.apk`（Android 8.0+，arm64；versionCode 46）和之前每个版本用同一把签名。校验：`sha256sum -c nanoMuse-1.0.3-arm64.apk.sha256`。底栏、抽屉和聊天的样子变了，其他什么都没挪。
- **iPhone 和 iPad 通过 TestFlight。** 公开链接装到的是通过了 Apple 测试版审核的第 16 个构建（1.0.0）；第 18 和第 19 个构建还在审核中，第 22 个构建（1.0.3）上传后送审；哪个构建审核通过，链接就给到哪个，内部测试员在那之前就能用。
- **桌面安装包由 CI 从 tag `v1.0.3` 之后一个提交的 `main` 构建**（tag 上的 Windows 构建卡在一个读换行符的测试上，已在 [#376](https://github.com/nano-muse/nanoMuse/pull/376) 修好；桌面端的源码和 tag 的一样）。 Mac 的包没有经过公证：第一次在「系统设置 → 隐私与安全性」里点「仍要打开」（或右键 → 「打开」）。Windows 的包没有签名：点一次「更多信息」和「仍要运行」。Linux 上优先用 `.deb`；AppImage 需要 FUSE（没有就加 `--appimage-extract-and-run`）。它们比 APK 晚一点到，`SHA256SUMS-desktop.txt` 列出了所有校验值。你原来那一个自定义端点成为新列表的第一项，key 留在原处。
- **中继是 0.24.2，线上什么都没变。** 1.0.2 的客户端对着它照常工作。它的 Docker 镜像现在以 uid 10001 运行，所以绑定挂载的数据目录必须属于这个 uid：执行一次 `sudo chown -R 10001:10001 data`（`scripts/self-host.sh` 会替你做），写不了目录的中继会在启动时说明，而不是打印一段 traceback；步骤见 [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/self-hosting.md)。
- **运行时的 HTTP API 少了一条路由。** `POST /api/avatar/estimate` 没有人调用；其他一切照旧，`config.toml` 里的每个键都保持原样。
