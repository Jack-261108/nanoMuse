# nanoMuse 1.0.6 · Beacon

🐉 **nanoMuse `1.0.6` “Beacon”**: nine days after Lookout, a third look at the whole project with the forty-eight pull requests that arrived in between; nanoMuse Cloud serves one multimodal model and leaves pictures and clips to a provider of your own, the relay's sign-in gives nothing away, the runtime finishes what a restart interrupted, the desktop asks before a restart, and the phone reads the Feed posts you liked.

1.0.5 went out on 2026-10-14. Since then forty-eight pull requests were merged, more than in any week before, and this version reads the project through once more with them in: the relay, the Python runtime, the web console, the desktop, the Android and iPhone apps, the docs and the workflows, area by area. The largest change is to the account: nanoMuse Cloud now serves one model, `Qwen/Qwen3.6-27B-FP8`, which reads text and pictures and does both the chat and the operating of a screen, and it no longer pays for image or video generation ([#536](https://github.com/nano-muse/nanoMuse/pull/536), [#539](https://github.com/nano-muse/nanoMuse/pull/539), [#545](https://github.com/nano-muse/nanoMuse/pull/545), [#546](https://github.com/nano-muse/nanoMuse/pull/546)). A drawn face, a picture asked for in a chat and the face's clips come from a provider of your own on every client, the pickers list only sources that can, and an empty row names who could; the default dragon and the four new preset looks are pictures already made, so a look is yours without a key. The relay is 0.27.0: a wrong password and an unknown account get the same answer, every limit is decided in one transaction, a Hub credential speaks for one device, and an invite bonus waits for real use ([#465](https://github.com/nano-muse/nanoMuse/pull/465)). The rest is the kind of thing a check finds: a reminder or a routine the runtime did not get to finish runs at the next start; the browser tool refuses local and private addresses as `web_fetch` always has; a streamed reply is retried only before its first word; restarting the desktop's Host asks first, as quitting does; a face drawn with your own key while signed out is worn rather than refused ([#521](https://github.com/nano-muse/nanoMuse/issues/521)); a remembered answer to an approval relayed from another device covers that step, not every step that starts the same way; hidden steps on the iPhone stay hidden after a reset ([#548](https://github.com/nano-muse/nanoMuse/issues/548)). Beside the check, @Mola-maker made forgetting a memory visible and undoable and gave the web console's settings a search ([#533](https://github.com/nano-muse/nanoMuse/pull/533), [#541](https://github.com/nano-muse/nanoMuse/pull/541)) and fixed nine things on Android and the desktop; @jiangkaiqi2005 taught the Windows desktop to download its updates in the background and install them on quit ([#458](https://github.com/nano-muse/nanoMuse/pull/458), [#459](https://github.com/nano-muse/nanoMuse/pull/459), [#460](https://github.com/nano-muse/nanoMuse/pull/460)); @cutey-none's `@` menu lists your other devices on the iPhone and a task sent to the desktop streams its text back ([#506](https://github.com/nano-muse/nanoMuse/pull/506), [#513](https://github.com/nano-muse/nanoMuse/pull/513), [#515](https://github.com/nano-muse/nanoMuse/pull/515)); @Battleplus added a fourth trigger kind and the data download ([#487](https://github.com/nano-muse/nanoMuse/pull/487), [#489](https://github.com/nano-muse/nanoMuse/pull/489)); @Yicheng-1218 let each avatar mood carry a clip of your own ([#427](https://github.com/nano-muse/nanoMuse/pull/427), [#481](https://github.com/nano-muse/nanoMuse/pull/481)); @isHeSatoshi put a search in the desktop's settings ([#523](https://github.com/nano-muse/nanoMuse/pull/523)); @hobostay kept a trimmed catalogue trimmed ([#527](https://github.com/nano-muse/nanoMuse/pull/527), [#530](https://github.com/nano-muse/nanoMuse/pull/530)); @henrikdukefoss added Standard Compute ([#482](https://github.com/nano-muse/nanoMuse/pull/482)); @fenghaofenghao-ctrl kept the Android Codex sign-in aligned with its live models ([#544](https://github.com/nano-muse/nanoMuse/pull/544)); @Longfellow1 began the goals' evidence evaluation ([#518](https://github.com/nano-muse/nanoMuse/pull/518)). Nothing moves for a person upgrading, except that pictures and clips need a key of your own from now on: the Android package installs over 1.0.5 and keeps everything, the desktop keeps its settings, and a 1.0.5 client works against the relay (0.27.0).

## Highlights

- **nanoMuse Cloud is one model, for chat and for the screen.** The account serves `Qwen/Qwen3.6-27B-FP8`, a multimodal model that reads pictures, so the chat and the hands run on the same deployment; the phone, the iPhone and the desktop pick the model the relay recommends for each of the two and still understand an older relay's menu. Bursts of chat no longer overwhelm the deployment: the relay admits a bounded number of chat requests at once, queues the rest and retries an upstream failure only before any output starts. A Qwen behind vLLM stays fast on ordinary turns when the app did not ask for reasoning ([#536](https://github.com/nano-muse/nanoMuse/pull/536), [#545](https://github.com/nano-muse/nanoMuse/pull/545), [#546](https://github.com/nano-muse/nanoMuse/pull/546)).
- **Pictures and clips come from a provider of your own.** nanoMuse Cloud stopped funding image and video generation: the *Making pictures* and *Making clips* rows on Android, the iPhone, the desktop and the web list only own providers that can, an empty row says who could and offers *Add a provider*, and asking the account for a picture is a sentence (`410 hosted_media_retired`) before anything is charged. Four original preset looks (Moss Courier, Tide Tinker, Dusk Moth, Copper Acorn) are pictures already made, in every language, next to the dragon, so a look needs no key; drawing your own does. Wan 2.7 is in the clip pickers of all three apps and speaks its own protocol ([#508](https://github.com/nano-muse/nanoMuse/issues/508)). On the desktop a face drawn with your own key while signed out is worn on that computer at once instead of being refused at the last step after nine paid pictures; a sign-in only shares it with your other devices ([#521](https://github.com/nano-muse/nanoMuse/issues/521), [#539](https://github.com/nano-muse/nanoMuse/pull/539)).
- **The relay's sign-in gives nothing away, and a credential is one device.** A wrong password, an unknown account and an account without a password get the same answer; the code's window, the number of tries, a code being used once and the number of accounts a mail domain may open a day are each decided inside one database transaction, so two requests at once cannot slip past a limit. Gmail's dot and plus aliases are one account, throwaway mail domains cannot open one, and an invite bonus is paid once the invitee's own use reaches a small threshold rather than when a device says hello ([#465](https://github.com/nano-muse/nanoMuse/pull/465)). Each account key owns one Hub identity, the device it was issued to; another device presenting it is refused with `bad_device`, and a fresh sign-in on the same installation takes the identity over.
- **The runtime finishes what it started.** A reminder, routine, goal pass, check-in or trigger that the runtime did not get to finish is written to a small outbox before it joins the chat's queue and runs at the next start. A streamed reply is retried only before its first word, so a half-written answer is never repeated; an MCP server whose tool names collide is skipped rather than half-loaded. The browser's `navigate` refuses `localhost`, private network addresses and a public page that redirects into them, as `web_fetch` always has. A long tool turn that fills the context window no longer sends the model a tool result whose call was cut off, by @takiAA ([#550](https://github.com/nano-muse/nanoMuse/pull/550)). A device of the account coming online is a fourth trigger kind, by @Battleplus ([#487](https://github.com/nano-muse/nanoMuse/pull/487)); the web console can download your agent data as one zip, by @Battleplus ([#489](https://github.com/nano-muse/nanoMuse/pull/489)); forgetting a memory is named in the chat and can be undone, by @Mola-maker ([#533](https://github.com/nano-muse/nanoMuse/pull/533)); Serply searches Google results with a key, Standard Compute is in the own-key catalogue, by @henrikdukefoss ([#482](https://github.com/nano-muse/nanoMuse/pull/482)), and the ChatGPT sign-in knows the GPT-6 series.
- **An approval relayed to another device is remembered for that step alone.** When the computer asks the phone whether a command may run and you answer *always*, the phone used to remember the answer by the first sixty characters of the card's text, so any later command that began the same way was allowed. The card now carries the Sentinel's own grant key, the tool and its whole command or path, and *always* and *for this chat* are kept on that; an older sender is remembered as before.
- **The desktop, in detail.** Restarting the Host (*Restart now* under the proxy row, and the restart macOS asks for after a Screen Recording grant) lists a reply, the hands, a task from another device or an approval still running and lets you keep them, as quitting does; a Host that no longer answers restarts without the question. The data export writes its zip one file at a time, leaves a link or a file over 64 MB out instead of stopping, and removes a proxy password. `desktop.json` is replaced atomically with the previous copy kept beside it. Windows downloads a ready update in the background on an unmetered network, offers it in the corner menu and installs it on a real quit, by @jiangkaiqi2005 ([#458](https://github.com/nano-muse/nanoMuse/pull/458), [#459](https://github.com/nano-muse/nanoMuse/pull/459), [#460](https://github.com/nano-muse/nanoMuse/pull/460)); the settings dialog has a search, by @isHeSatoshi ([#523](https://github.com/nano-muse/nanoMuse/pull/523)); a trimmed provider catalogue stays trimmed in the pickers, by @hobostay ([#527](https://github.com/nano-muse/nanoMuse/pull/527)); each avatar mood can carry a clip of your own, by @Yicheng-1218 ([#427](https://github.com/nano-muse/nanoMuse/pull/427)); a task from the phone streams its text back while the model writes it, by @cutey-none ([#515](https://github.com/nano-muse/nanoMuse/pull/515)); the chat's model control is back in the composer, going back no longer returns to the starting screen ([#492](https://github.com/nano-muse/nanoMuse/pull/492), @jiangkaiqi2005), synced turns from another computer keep their order, and the bundled runtime keeps its links, its start-up check no longer hangs and the Mac packaging stops on a failed check instead of shipping past it ([#467](https://github.com/nano-muse/nanoMuse/pull/467), [#469](https://github.com/nano-muse/nanoMuse/pull/469), [#471](https://github.com/nano-muse/nanoMuse/pull/471), @Mola-maker).
- **Android and the iPhone.** The Android agent can read which Feed posts you liked, as files in its sandbox under `/var/minis/feed/`, read-only ([#547](https://github.com/nano-muse/nanoMuse/issues/547)); the Codex sign-in stays aligned with its live models, by @fenghaofenghao-ctrl ([#544](https://github.com/nano-muse/nanoMuse/pull/544)); voice input releases the recorder when capture cannot start, a quiet provider voice session returns to idle, a replaced set of avatar candidates is never changed by an old result, and an emulator build leaves the arm64 sandbox out, all by @Mola-maker ([#358](https://github.com/nano-muse/nanoMuse/pull/358), [#359](https://github.com/nano-muse/nanoMuse/pull/359), [#466](https://github.com/nano-muse/nanoMuse/pull/466), [#468](https://github.com/nano-muse/nanoMuse/pull/468), [#472](https://github.com/nano-muse/nanoMuse/pull/472), [#473](https://github.com/nano-muse/nanoMuse/pull/473)); memory and date changes no longer invalidate the prompt prefix the provider caches ([#503](https://github.com/nano-muse/nanoMuse/pull/503)). On the iPhone, turning off execution steps survives resetting and reopening the main conversation ([#548](https://github.com/nano-muse/nanoMuse/issues/548)); the `@` menu offers your other devices and a task sent with `@〈device〉` shows its progress, by @cutey-none ([#506](https://github.com/nano-muse/nanoMuse/pull/506), [#513](https://github.com/nano-muse/nanoMuse/pull/513)); a picked avatar clip keeps its preview open, by @Yicheng-1218 ([#481](https://github.com/nano-muse/nanoMuse/pull/481)); the drawer, the composer and the step bar line up, by @cutey-none ([#462](https://github.com/nano-muse/nanoMuse/pull/462)).
- **The project.** The *Community Contributors* avatars in the ten READMEs are current; `scripts/release-apk.sh` stops rather than publish a release without its pull-request list, and the desktop workflow refuses to attach installers of another version to a release; the bug report form is back on the new-issue chooser, by @Battleplus ([#496](https://github.com/nano-muse/nanoMuse/pull/496)); the docs name the macOS helper as the entry to switch on, count four trigger kinds and say that TestFlight is run by hand.
- **TestFlight.** Build 28 (1.0.5) was submitted to Apple's beta review on 2026-10-14; 1.0.6 goes up as build 29 and is submitted to the same review. A build reaches the public link once its review has passed, the internal testers before that.

## Upgrade Notes

- **Android installs over 1.0.5 and keeps your data.** `nanoMuse-1.0.6-arm64.apk` (Android 8.0+, arm64; versionCode 49) is signed with the same key as every version before it. Verify with `sha256sum -c nanoMuse-1.0.6-arm64.apk.sha256`. If *Making pictures* or *Making clips* pointed at nanoMuse Cloud, the row is empty now and names who could; add a provider of your own under Settings → Models. A face you already drew stays.
- **iPhone and iPad come through TestFlight.** Build 29 (1.0.6) is submitted when it is uploaded and reaches the public link once its review has passed, the internal testers before that; until then the link installs the newest build that passed.
- **The desktop installers are built by CI from the tag `v1.0.6`.** The Mac packages are not notarized: the first time, open the app from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*). The Windows package is not signed: click *More info* and *Run anyway* once. On Linux prefer the `.deb`; the AppImage needs FUSE (`--appimage-extract-and-run` without). They arrive a little after the APK, and `SHA256SUMS-desktop.txt` lists every checksum. A 1.0.5 desktop on Windows can take this version from inside the app; from this version on, an update downloads in the background on an unmetered network, the corner menu offers it, and a real quit installs it. Your settings stay where they were; `desktop.json` gains a `.bak` copy beside it on its next write.
- **The relay is 0.27.0; a 1.0.5 client works against it unchanged**, except that asking the account for a picture or a clip is refused with `410 hosted_media_retired` and a sentence. For operators: `DASHSCOPE_KEY` is a second, optional key for a self-hosted relay that keeps its media proxy on (`CLOUD_MEDIA_ENABLED=1`); `CLOUD_MODEL_ALIASES` maps model ids saved by older clients to the current menu; `CHAT_DEFAULTS` understands `chat_template_kwargs.enable_thinking`; `SIGNUP_PER_DOMAIN_DAY` defaults to 5 for domains that are not well known, `SIGNUP_DOMAIN_BLOCK` and `SIGNUP_DOMAIN_ALLOW` adjust the throwaway-domain list, `INVITE_SETTLE_MIN_SPENT_UY` (200) is the use an invitee must reach before the bonus is paid; `POST /v1/auth/verify` and `/login` take an optional `device_id` and `device_kind`, and the hub refuses a key presented by another device with `bad_device`; `+tag` addresses are separate accounts at providers other than Gmail from now on, and an account that 0.26 merged under the plain address is still reached by both. [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/self-hosting.md), [docs/hub.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/hub.md) and [cloud/README.md](https://github.com/nano-muse/nanoMuse/blob/main/cloud/README.md) have the details.
- **The runtime writes one more file and refuses one more thing.** `scheduled-deliveries.db` beside the other state files is the outbox that lets interrupted scheduled work run at the next start. The browser tool's `navigate` refuses `localhost` and private network addresses, as `web_fetch` does; a page on your own machine is still reachable through a tunnel with a public name. Nothing in `config.toml` changes.

## Community

nanoMuse is open source, free and non-profit. Sign in with a phone number or an e-mail and you get a starting allowance; the developer pays for it. The account page shows what is left and how to add more. When it is gone, use your own key or a plan you already pay for ([how](https://github.com/nano-muse/nanoMuse/blob/main/docs/own-key.md)); the key you add can take over the chat and the screen, and pictures and clips are its from the start; the account can be switched off as a model source while you keep it for sync and your devices. With an account, the text of your main conversation is kept on nanoMuse Cloud so that your devices show the same chat, side chats only if you say so, and one switch in Data controls turns it off and deletes it; nothing is sold ([privacy policy](https://nanomuse.cn/privacy/)); delete the account whenever you want. The same relay runs on a server of yours: [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/self-hosting.md).

### 亮点

- **nanoMuse Cloud 只有一个模型，聊天和屏幕都用它。** 账号提供 `Qwen/Qwen3.6-27B-FP8`，一个能看图的多模态模型，所以聊天和手跑在同一个部署上；手机、iPhone 和桌面端各自按中继对这两件事的推荐来选，也仍然认得旧中继的菜单。一阵聊天高峰不再压垮部署：中继同时只放进有限数量的聊天请求，其余排队，上游出错只在还没输出任何内容时重试。vLLM 后面的 Qwen 在应用没要求推理的普通轮次上保持快速（[#536](https://github.com/nano-muse/nanoMuse/pull/536)、[#545](https://github.com/nano-muse/nanoMuse/pull/545)、[#546](https://github.com/nano-muse/nanoMuse/pull/546)）。
- **图片和短片来自你自己的服务商。** nanoMuse Cloud 不再出生图和生视频的钱：Android、iPhone、桌面端和网页上的「生成图片」「生成短片」两行只列能做这件事的自有服务商，空着的一行会说谁能做并给出「添加服务商」，向账号要图在扣任何费用之前就得到一句话（`410 hosted_media_retired`）。四个原创预设形象（Moss Courier、Tide Tinker、Dusk Moth、Copper Acorn）是现成的图片，每种语言都有，和小龙并排，所以要一张脸不用 key；自己画才要。Wan 2.7 进了三个 App 的短片选择器，并按它自己的协议说话（[#508](https://github.com/nano-muse/nanoMuse/issues/508)）。桌面端没登录时用自己的 key 画的脸会立刻穿在这台电脑上，而不是花了九张图的钱后在最后一步被拒；登录只负责把它同步到你的其他设备（[#521](https://github.com/nano-muse/nanoMuse/issues/521)、[#539](https://github.com/nano-muse/nanoMuse/pull/539)）。
- **中继的登录入口什么都不泄露，一把凭据就是一台设备。** 错密码、不存在的账号和没设密码的账号得到同样的回答；验证码的时间窗、尝试次数、一个码只用一次、一个邮箱域名一天能开几个账号，各自在一个数据库事务里判定，两个同时到的请求不可能溜过限额。Gmail 的点号和加号别名是同一个账号，一次性邮箱域名开不了账号，邀请奖励等被邀请的人自己的用量到一个小门槛才发，而不是设备打个招呼就发（[#465](https://github.com/nano-muse/nanoMuse/pull/465)）。每把账号 key 只拥有一个 Hub 身份，就是签发给它的那台设备；别的设备拿着它来会被 `bad_device` 拒绝，同一台安装上重新登录会接管这个身份。
- **运行时把开了头的事做完。** 运行时没来得及做完的提醒、例程、目标检查、问候或触发器，在进聊天队列之前先写进一个小小的发件箱，下次启动时补跑。流式回复只在第一个字之前重试，所以写了一半的回答不会重复；工具名冲突的 MCP 服务器整个跳过，而不是加载一半。浏览器的 `navigate` 拒绝 `localhost`、内网地址和跳转进内网的公开页面，和 `web_fetch` 一向一样。填满上下文窗口的长工具轮次不再把砍掉了调用的工具结果发给模型，@takiAA 修的（[#550](https://github.com/nano-muse/nanoMuse/pull/550)）。账号下一台设备上线是第四种触发器，@Battleplus 做的（[#487](https://github.com/nano-muse/nanoMuse/pull/487)）；网页控制台能把你的智能体数据打成一个 zip 下载，也是 @Battleplus（[#489](https://github.com/nano-muse/nanoMuse/pull/489)）；忘掉一条记忆会在聊天里点名并能撤销，@Mola-maker 做的（[#533](https://github.com/nano-muse/nanoMuse/pull/533)）；Serply 用 key 搜 Google 结果，Standard Compute 进了自有 key 目录，@henrikdukefoss 加的（[#482](https://github.com/nano-muse/nanoMuse/pull/482)），ChatGPT 登录认得 GPT-6 系列。
- **转给别的设备的审批只记住那一步。** 电脑问手机一条命令能不能跑、你答「总是」时，手机以前按卡片文字的前六十个字符记住这个回答，所以之后任何开头一样的命令都放行了。卡片现在带着 Sentinel 自己的授权键，也就是工具加上完整的命令或路径，「总是」和「这个对话里」都记在它上面；旧版发来的照旧记。
- **桌面端的细节。** 重启 Host（代理那一行的「立即重启」，以及 macOS 给了录屏权限后要求的重启）会列出还在进行的回复、手、别的设备发来的任务或审批，让你选择保留，和退出一样；不再应答的 Host 不问直接重启。数据导出一次写一个文件进 zip，遇到链接或超过 64 MB 的文件跳过而不是中断，并去掉代理密码。`desktop.json` 原子替换，旧副本留在旁边。Windows 在非计费网络上后台下载好更新，在角落菜单里给出，真正退出时安装，@jiangkaiqi2005 做的（[#458](https://github.com/nano-muse/nanoMuse/pull/458)、[#459](https://github.com/nano-muse/nanoMuse/pull/459)、[#460](https://github.com/nano-muse/nanoMuse/pull/460)）；设置对话框有了搜索，@isHeSatoshi 做的（[#523](https://github.com/nano-muse/nanoMuse/pull/523)）；裁剪过的服务商模型目录在选择器里保持裁剪，@hobostay 做的（[#527](https://github.com/nano-muse/nanoMuse/pull/527)）；每种心情都能放你自己的短片，@Yicheng-1218 做的（[#427](https://github.com/nano-muse/nanoMuse/pull/427)）；手机发来的任务在模型写的时候就把文字流回去，@cutey-none 做的（[#515](https://github.com/nano-muse/nanoMuse/pull/515)）；聊天的模型控件回到了输入框，返回不再跳回起始屏（[#492](https://github.com/nano-muse/nanoMuse/pull/492)，@jiangkaiqi2005），另一台电脑同步来的轮次保持顺序，随附的运行时保留它的链接、启动检查不再挂住、Mac 打包遇到检查失败就停下而不是带着问题出包（[#467](https://github.com/nano-muse/nanoMuse/pull/467)、[#469](https://github.com/nano-muse/nanoMuse/pull/469)、[#471](https://github.com/nano-muse/nanoMuse/pull/471)，@Mola-maker）。
- **Android 和 iPhone。** Android 的智能体能读到你点赞了哪些动态，以只读文件的形式放在沙盒的 `/var/minis/feed/` 下（[#547](https://github.com/nano-muse/nanoMuse/issues/547)）；Codex 登录跟上它的模型列表，@fenghaofenghao-ctrl 做的（[#544](https://github.com/nano-muse/nanoMuse/pull/544)）；录音起不来时语音输入会释放录音器，安静的服务商语音会话会回到空闲，换掉的一批形象候选不会被旧结果改掉，模拟器构建不带 arm64 沙盒，都是 @Mola-maker（[#358](https://github.com/nano-muse/nanoMuse/pull/358)、[#359](https://github.com/nano-muse/nanoMuse/pull/359)、[#466](https://github.com/nano-muse/nanoMuse/pull/466)、[#468](https://github.com/nano-muse/nanoMuse/pull/468)、[#472](https://github.com/nano-muse/nanoMuse/pull/472)、[#473](https://github.com/nano-muse/nanoMuse/pull/473)）；记忆和日期的变化不再让服务商缓存的提示词前缀失效（[#503](https://github.com/nano-muse/nanoMuse/pull/503)）。iPhone 上，关掉执行步骤后重置并重新打开主对话也保持关着（[#548](https://github.com/nano-muse/nanoMuse/issues/548)）；`@` 菜单给出你的其他设备，用 `@〈设备〉` 发出去的任务能看到进度，@cutey-none 做的（[#506](https://github.com/nano-muse/nanoMuse/pull/506)、[#513](https://github.com/nano-muse/nanoMuse/pull/513)）；选好的形象短片预览保持打开，@Yicheng-1218 做的（[#481](https://github.com/nano-muse/nanoMuse/pull/481)）；抽屉、输入框和步骤栏对齐了，@cutey-none 做的（[#462](https://github.com/nano-muse/nanoMuse/pull/462)）。
- **项目本身。** 十个 README 里的「社区贡献者」头像是最新的；`scripts/release-apk.sh` 在 PR 列表生成不出来时停下，而不是发一个缺了它的版本，桌面工作流拒绝把另一个版本的安装包挂到一个发布上；bug 报告表单回到了新建 issue 的选择页，@Battleplus 做的（[#496](https://github.com/nano-muse/nanoMuse/pull/496)）；文档把 macOS 的助手程序写成要打开的那一项，触发器数成四种，并说明 TestFlight 是手动触发的。
- **TestFlight。** 第 28 个构建（1.0.5）在 2026-10-14 提交了 Apple 的测试版审核；1.0.6 以第 29 个构建上传并提交同一审核。审核通过的构建就会给到公开链接，内部测试员在那之前就能用。

### 升级说明

- **Android 覆盖安装 1.0.5，数据保留。** `nanoMuse-1.0.6-arm64.apk`（Android 8.0+，arm64；versionCode 49）和之前每个版本用同一把签名。校验：`sha256sum -c nanoMuse-1.0.6-arm64.apk.sha256`。如果「生成图片」或「生成短片」之前指向 nanoMuse Cloud，这一行现在是空的，会说谁能做；在「设置 → 模型」里添加你自己的服务商。已经画好的脸还在。
- **iPhone 和 iPad 通过 TestFlight。** 第 29 个构建（1.0.6）上传后送审，审核通过就给到公开链接，内部测试员在那之前就能用；在那之前链接装到的是最近一个通过审核的构建。
- **桌面安装包由 CI 从 tag `v1.0.6` 构建。** Mac 的包没有经过公证：第一次在「系统设置 → 隐私与安全性」里点「仍要打开」（或右键 → 「打开」）。Windows 的包没有签名：点一次「更多信息」和「仍要运行」。Linux 上优先用 `.deb`；AppImage 需要 FUSE（没有就加 `--appimage-extract-and-run`）。它们比 APK 晚一点到，`SHA256SUMS-desktop.txt` 列出了所有校验值。Windows 上的 1.0.5 桌面端可以在应用内升到这个版本；从这个版本起，更新在非计费网络上后台下载，角落菜单给出，真正退出时安装。你的设置原地不动；`desktop.json` 下次写入时旁边会多一个 `.bak` 副本。
- **中继是 0.27.0，1.0.5 的客户端对着它照常工作**，只有向账号要图或要短片会被 `410 hosted_media_retired` 和一句话拒绝。给运维的人：`DASHSCOPE_KEY` 是给仍开着媒体代理（`CLOUD_MEDIA_ENABLED=1`）的自建中继用的第二把可选 key；`CLOUD_MODEL_ALIASES` 把旧客户端存下的模型 id 映射到当前菜单；`CHAT_DEFAULTS` 认得 `chat_template_kwargs.enable_thinking`；不知名域名的 `SIGNUP_PER_DOMAIN_DAY` 默认是 5，`SIGNUP_DOMAIN_BLOCK` 和 `SIGNUP_DOMAIN_ALLOW` 调整一次性邮箱域名的名单，`INVITE_SETTLE_MIN_SPENT_UY`（200）是被邀请的人要用到多少奖励才发；`POST /v1/auth/verify` 和 `/login` 接受可选的 `device_id` 和 `device_kind`，hub 用 `bad_device` 拒绝别的设备拿来的 key；从现在起 Gmail 以外的 `+tag` 地址是独立账号，0.26 合并到原地址下的账号两边都还能登进去。细节见 [docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/self-hosting.md)、[docs/hub.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/hub.md) 和 [cloud/README.md](https://github.com/nano-muse/nanoMuse/blob/main/cloud/README.md)。
- **运行时多写一个文件，多拒绝一件事。** 其他状态文件旁边的 `scheduled-deliveries.db` 是让被打断的计划任务在下次启动时补跑的发件箱。浏览器工具的 `navigate` 像 `web_fetch` 一样拒绝 `localhost` 和内网地址；你自己机器上的页面仍然可以通过有公开域名的隧道访问。`config.toml` 里什么都不变。

### 社区

nanoMuse 开源、免费、非营利。手机号或邮箱登录后有一份起始额度，钱是开发者出的；剩多少、怎么加，账号页里有数。用完可以换成自己的 key，或者用你已经在付费的套餐登录（[教程](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/own-key.md)）；你加的 key 可以接手聊天和屏幕，图片和短片从一开始就是它的；账号也可以作为模型来源关掉，只留着做同步和管设备。登录后，主聊天的文字会保存在 nanoMuse Cloud，让你的几台设备看到同样的对话，旁聊只在你说要的时候才上去；「数据控制」里一个开关就能关掉并删除；数据不卖（[隐私政策](https://nanomuse.cn/privacy/)）；账号想删就删。同一个中继也能跑在你自己的服务器上：[docs/self-hosting.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/zh/self-hosting.md)。
